Требования к внешним интеграциям

1) Требования к безопасности:
- Все взаимодействия должны осуществляться только по защищённым каналам(TLS 1.3).
- Обязательная проверка TLS сертификатов.
- Внешние системы должны получить только необходимую информацию для выполнения операций. 
- Обязательна токенизация и маскирование персональных данных, если недопустимо, то шифрование.
- Разные endpoint для операций со шлагбаумом и домофоном и разные разрешения. 
- Логирование операций.
- Выполнение требований ФЗ-152.
 
2) Протоколы аутентификации и авторизации:
- Пользователи(клиенты, собственники, сотрудники) используют логин и пароль для доступа к ИС.
- Для взаимодействия между микросервисами и внешними системами используется M2M token с ограниченным временем жизни.
- Принцип least privilege.
- Регулярная ротация ключей и токенов, политики обновления паролей. 
- Хранение секретов в Vault.

3) Организация взаимодействия между системами предприятия и внешней платформой:
- API Gateway является единой точкой входа для всех внешних интеграций.
- Только синхронное взаимодействие по протоколу REST.
- Формат данных - JSON.
- Наличие Timeout, Retry и Circuit Breaker.

### Важные моменты
Партнерская система взаимодействует через API Gateway, используя токен. Токен получается путем предоставления mTLS сертификата.
Рассмотрим пример - открытие шлагбаума по номеру автомобиля.

Шаг 1: К шлагбауму подъезжает машина.

Шаг 2: Партнерская система распознает номер.

Шаг 3: Партнерская система шифрует номер и выполняет запрос на разрешение въезда в ИС Умный Дом.

Шаг 4: Запрос проходит через Firewall.

Шаг 5: Запрос попадает на API Gateway.

Шаг 6: Проверка токена.

Шаг 7: Если токен валидный, то передача сообщения в сервис взаимодействия с домофоном и шлагбаумом. 

Шаг 8: Сервис проверяет номер, если номер есть в базе, то отправляет ответ на открытие.
